# Software Requirements Specification (SRS)

**Standard:** IEC 62304 §5.2 · **Status:** Draft · **Last updated:** 2026-04-26 · **Owner:** Vivek Sah

## 1. Purpose

Numbered, testable software requirements for `@viveksah/vibe-native-dicom`. Each requirement has:

- ID (`SR-XXXX`)
- Title
- Description (what the system shall do)
- Rationale / source (why)
- Verification method (how it'll be tested)
- Phase (when it's implemented)
- Status (Draft / Approved / Implemented / Verified)

## 2. ID conventions

- `SR-0xxx` — system-level (functional)
- `SR-1xxx` — performance / non-functional
- `SR-2xxx` — security / privacy
- `SR-3xxx` — usability / API ergonomics
- `SR-9xxx` — process / build / CI

IDs are never reused. Once a requirement is retired it is marked **Obsolete** and kept for history.

## 3. Requirements

> _Filled in iteratively. Phase 0 establishes only process requirements; Phase 1 adds functional requirements._

### Phase 2 — DICOM I/O

| ID | Title | Description | Rationale | Acceptance | Priority | Status |
| --- | --- | --- | --- | --- | --- | --- |
| SR-0011 | Read DICOM file metadata + uncompressed pixel data | The package shall expose a synchronous JS function `readDicom(path: string): DicomFile` that opens a DICOM file from a local filesystem path, parses the file meta information and dataset, returns the SOP Class/Instance UIDs and transfer syntax UID, returns every top-level data element keyed by `"GGGG,EEEE"` hex, and (for Implicit VR LE / Explicit VR LE files containing PixelData) returns the uncompressed pixel buffer as base64. Compressed transfer syntaxes shall return all metadata but with `image.hasPixelData = false`; the function shall not silently return wrong pixel data. The function shall throw a JS exception on (a) unreadable / non-DICOM input or (b) GDCM-side parse failures. The same function shall return the same `transferSyntaxUID`, `sopClassUID`, `sopInstanceUID`, `dataset` keys, image attributes, and `pixelDataBase64` value on iOS and Android for the same input file. | First user-facing DICOM API; everything in Phase 3+ depends on it. The strict "throw on unreadable, leave pixels empty on unsupported syntax" rule prevents the most dangerous failure mode for diagnostic software — a viewer rendering whatever bytes it found and presenting them as the patient's image. | (i) Round-trip smoke: `writeSyntheticDicom()` followed by `readDicom()` returns the synthesized file's metadata + 256-byte uncompressed pixel buffer (16×16×8-bit) on both iOS and Android. (ii) Dataset element count ≥ 12 (the minimum required Type 1 attributes for MR Image Storage). (iii) Patient Name (0010,0010) round-trips byte-for-byte. (iv) Jest contract test asserts the documented JS surface shape. | 1 | In progress |
| SR-0012 | Synthesize a minimal valid DICOM for round-trip testing | The package shall expose `writeSyntheticDicom(transferSyntaxUID: string): string` that writes a 16×16 monochrome 8-bit MR Image Storage SOP file (with a deterministic gradient pixel buffer) to platform tmpdir in the requested transfer syntax and returns the path. Empty UID defaults to Implicit VR Little Endian. Unsupported UIDs raise an exception. The synthesized file shall validate as a DICOM under both `gdcm::Reader` and `gdcm::ImageReader`. | Phase 2 ships before fixture-loading work, so the example app and integration tests need a self-contained smoke target that covers every supported syntax. | (i) The returned path is a writable file. (ii) `readDicom()` of the returned path succeeds and reports MR Image Storage (1.2.840.10008.5.1.4.1.1.4) as `sopClassUID`. (iii) For each transfer syntax accepted by `isSupportedTransferSyntax()`, the round-trip succeeds; for at least one unsupported UID the call throws. | 2 | In progress |
| SR-0013 | Decode the compressed DICOM transfer syntaxes that GDCM ships out of the box | The package shall decode pixel data for: Implicit VR LE, Explicit VR LE, JPEG Baseline (Process 1), JPEG Extended (Processes 2 & 4), JPEG Lossless P14, JPEG Lossless P14 SV1, JPEG-LS Lossless, JPEG-LS Near-Lossless, JPEG 2000 Lossless, JPEG 2000 (lossy), and RLE Lossless — i.e. the eleven syntaxes returned `true` by `isSupportedTransferSyntax()`. For lossless syntaxes pixel-buffer length and content shall round-trip byte-for-byte against `writeSyntheticDicom(uid)`. For lossy syntaxes the decoder shall return a non-empty pixel buffer of the expected dimensions (16×16 = 256 bytes for the synthetic image). For any UID NOT on the whitelist (e.g. MPEG2MainProfile `1.2.840.10008.1.2.4.100`, HTJ2K, Deflated, big-endian) `readDicom` shall return `image.hasPixelData = false` and `pixelDataBase64 = null` instead of substituting undefined bytes. The package shall also expose `isSupportedTransferSyntax(uid: string): boolean` so callers can probe support before invoking the decoder. | Compressed transfer syntaxes are the dominant on-the-wire representation in real PACS deployments — most CT/MR/CR studies arrive as JPEG 2000 Lossless or JPEG Lossless P14. Without decode support the package can't read clinical data. The hard rule "fail loudly on unsupported syntaxes" is the live mitigation for hazard H-021 (silent pixel-data substitution → wrong-image diagnosis). | (i) `isSupportedTransferSyntax` returns true for each documented UID and false for at least one out-of-whitelist UID. (ii) `writeSyntheticDicom(uid)` followed by `readDicom()` produces `image.hasPixelData=true` for every supported UID. (iii) Lossless UIDs return exactly 256 pixel-data bytes (16×16×8-bit). (iv) Negative test: `writeSyntheticDicom('1.2.840.10008.1.2.4.100')` throws "unsupported transfer syntax UID". (v) Verified end-to-end on iOS simulator and Android emulator via the example app's per-syntax PASS/FAIL grid. | 1 | In progress |
| SR-0014 | Recursive traversal of DICOM Sequence (SQ) elements | `readDicom()` shall represent every top-level SQ element as `{ vr: 'SQ', value: null, items: DicomDataset[] }` where each item is itself a fully-walked `DicomDataset`. Recursion shall be unbounded (capped only by GDCM's own parser-side limits) so deeply nested IODs (Structured Reports, RT Plan, Spatial Registration) read correctly. Empty SQs (DICOM Type 2 zero-item) shall be represented as `items: []`, distinct from "tag absent". Non-SQ elements shall NOT have an `items` property. PixelData (7FE0,0010) is excluded from the dataset walk; it remains accessible via `image.pixelDataBase64`. | The DICOM IODs we eventually need (Structured Reports, RT Plan, Segmentation, Presentation States) are SQ-heavy. Without recursive traversal a viewer can read the SOP class but not the actual content. Phase 2.1 emitted SQ as empty strings — that was a known stub. | (i) `writeSyntheticDicom('')` includes a Procedure Code Sequence (0008,1032) with one item; `readDicom()` returns `dataset['0008,1032'].vr === 'SQ'`, `value === null`, `items.length === 1`, and the item contains the embedded `(0008,0100)`/`(0008,0102)`/`(0008,0104)` triple. (ii) Empty SQs (0040,0260) round-trip as `items: []`. (iii) Non-SQ elements (e.g. PatientName) have `items === undefined`. (iv) iOS NSDictionary and Android WritableMap representations both serialize the recursive shape (verified via clean-tree builds). | 1 | In progress |
| SR-0015 | Ergonomic accessors for common viewer tags | The package shall export pure-TS helper functions for the DICOM tags a 2D viewer commonly needs: Patient (Name/ID/BirthDate/Sex), Study (InstanceUID/Date/Time/Description/AccessionNumber), Series (InstanceUID/Number/Description/Modality), SOP/Image (InstanceUID/Number), pixel geometry (PixelSpacing as `[row,col]`), and VOI/rescale (WindowCenter/WindowWidth/RescaleSlope/RescaleIntercept). Each helper shall: (a) return `null` rather than throw when the tag is missing or its value is empty; (b) return `null` rather than `NaN` when a numeric VR (DS / IS) fails to parse — viewers must never render garbage values; (c) be pure functions of a `DicomDataset`, with no native-side calls. | Viewer code (Phase 3+) needs hundreds of `dataset['GGGG,EEEE']?.value` patterns without these. Centralising the lookups stops typo-by-tag bugs (`'0010,1010'` vs `'0010,0010'`) and gives one place to fix per-tag parsing quirks. | (i) Each helper exists and is exported from the package surface. (ii) Helpers return the documented value for a populated tag. (iii) Helpers return `null` for absent tags and present-but-empty tags. (iv) Numeric helpers return `null` (not NaN) for malformed values. (v) Pixel-spacing helper returns `[row, col]` in the documented order. | 1 | In progress |
